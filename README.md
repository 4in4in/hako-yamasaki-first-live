# Хако Ямасаки – «Первый концерт» / 山崎ハコ・ファーストライブ

Русский перевод и транскрипция всех песен концертного альбома
Хако Ямасаки «First Live» (1976), с примечаниями и переводом
реплик между композициями.

Готовый PDF: **https://4in4in.github.io/hako-yamasaki-first-live/**

## Структура

```
src/main.typ            общий макет, колонтитулы, порядок разделов
src/meta.typ            автор, годы, лицензия — то, что печатается на титуле и в подвале
src/lib.typ             функции song / appendix / lyrics
src/front.typ           титульный лист
src/transcription.typ   «О транскрипции»
src/songs/*.typ         по файлу на песню
src/appendix/*.typ      приложения
fonts/                  Zen Antique (SIL OFL)
site/                   страница для GitHub Pages
scripts/build.sh        локальная сборка PDF
```

Каждая песня — это файл вида:

````typst
#import "../lib.typ": *
#show: song.with("ハーモニカ吹き男", "Гармонист", note: [примечание к названию])

```lyrics
название | название в транскрипции | название по-русски

японский | транскрипция | перевод
японский | транскрипция | перевод

японский | транскрипция | перевод
```
````

Каждая строка блока `lyrics` — строка таблицы, ячейки разделены `|`.
Пустая строка — промежуток между строфами. Первая строфа из одной строки
считается заголовочным рядом и выделяется жирным. Внутри ячейки можно
использовать разметку Typst, например `#footnote[...]`.

## Сборка

Нужен [Typst](https://typst.app/) 0.13 или новее.

```sh
scripts/build.sh          # build/hako-yamasaki-first-live.pdf
scripts/build.sh watch    # пересборка при каждом сохранении
scripts/build.sh png      # плюс страницы в build/png/
scripts/build.sh open     # собрать и открыть PDF
```

Скрипт ищет `typst` в PATH и в `~/.local/bin`. Та же команда вручную:

```sh
typst compile --root . --font-path fonts src/main.typ build/hako-yamasaki-first-live.pdf
```

## Публикация

При каждом пуше в `main` GitHub Actions только собирает PDF и проверяет,
что сборка проходит. Публикация происходит по тегу вида `v*`: PDF вместе
со страницей из `site/` выкладывается на GitHub Pages и прикрепляется
к GitHub Release.

```sh
git tag v1.1
git push --tags
```

Если изменилась только страница в `site/`, сайт можно передеплоить без
новой версии документа: PDF при этом берётся из последнего Release.

```sh
gh workflow run deploy.yml --ref main
```
